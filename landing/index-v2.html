Execution modes

三种模式，不是三套引擎。
共享记忆、工具与快照。

难易不同的任务，用不同的思考方式。切换的是策略，沉淀的是同一份对代码库的理解。

ReAct/ 边想边干

单代理循环：Thought → Action → Observation。一边推理一边调用工具，把一句话需求立刻办成。日常顺手的小事，它最利落。

10+ 内置工具web_searchHITL
$ paicli "把这个报错查一下并修好"
Plan-and-Execute/ 先计划，再动手

复杂任务先拆解成带依赖关系的 DAG，与你在动手前逐项确认。会牵一发动全身的大改，它每一步都让你看得见、拦得住。

/planDAG 依赖执行前确认
$ /plan "给整个模块加缓存与限流"
Multi-Agent/ 组队干活

Planner 拆解、Worker 执行、Reviewer 审查——审查不过就带反馈重试，冲突自动收敛。适合需要质量门槛的批量工程活。

/team评审循环自动返工
$ /team "重构遗留模块，保持行为不变"

三条路径共享 ToolRegistry / MemoryManager / SnapshotService——不会为某个模式制造孤立的能力孤岛。 各模式细节见 README 的演进记录。

Quick start

三个命令，
它今晚就进你的终端。

1

准备环境

Java 17+ 与 Maven，构建默认跳过测试，优先产出可手工验收的 jar。

2

写入模型配置

首次启动自动生成 ~/.paicli，填入任一已适配国产模型的 Key。

3

把第一句话交给它

从一个真实的小任务开始——让它在你的仓库里替你完成第一件事。

Java 17+ · Maven 3.8+ macOS / Linux 用 java -jar 启动 
# 1 · 构建（默认跳过测试，直接产出 jar）
$ mvn clean package

# 2 · 启动（Windows 可双击 start-paicli.bat）
$ java -jar target/paicli-1.0-SNAPSHOT.jar

# 3 · 进入 TUI 后，把需求直接说给它
> "帮我把 UserService 里重复的 try-catch 抽出来"

完整命令、TUI 快捷键与模式入口记录在根目录 README.md，演进计划见 ROADMAP.md。
